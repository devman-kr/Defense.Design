## 2. 쓰는 법

1. **결정이 먼저, 기획서가 다음.** 기획을 바꾸는 지시를 받으면 Planning 과제 `결정기록.md` 에 D-nn 을 남기고 이 저장소 문서를 고친다. 각 절에는 근거 D-nn 을 적는다.
2. **기획서는 덮어쓴다.** 옛 내용은 git 이력과 결정기록이 보존한다. 문서 안에 변경 이력 절을 두지 않고, 맨 위 판 표시(v0.n · 날짜 · 바뀐 절)만 갱신한다.
3. **코드가 기획서보다 앞서가지 않는다**(루트 `CLAUDE.md`). Unity 저장소는 이 저장소의 기획서를 참조한다.
4. 수치에는 「초안」을 달고, 측정 · 플레이검사로 정한 값은 빌드 · 기기 · 날짜를 함께 적는다.
5. 표기는 Planning `README.md` 4절과 같다 — 마크다운, 이모지 금지, 한글 그대로, 직접 확인 ✔ · 에이전트 보고 △ · 추정 [추정]. 비밀값 금지.
6. 레퍼런스(Supercent) 게임의 에셋 · 캡처는 넣지 않는다 — 스타일 보드(`../../../_공통/조사/`)에만(G-02 · G-03). 문서에 넣는 그림은 직접 만든 것만 `assets/` 에.
